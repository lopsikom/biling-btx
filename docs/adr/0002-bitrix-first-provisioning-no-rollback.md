# 2. Провижининг модуля: Bitrix-first, без отката БД→Bitrix

Дата: 2026-06-18
Статус: Принято

## Контекст

При создании модуля в виджете (`module provisioning`, см. [CONTEXT.md](../../CONTEXT.md))
происходят два последовательных, неатомарных шага:

1. запись `product` в Bitrix (`setProductBitrix` — product row + offer);
2. запись строки модуля в БД (`post*Prisma`).

Между шагами нет общей транзакции. Возможен сбой: Bitrix-товар создан, а запись в БД
упала (или наоборот). Возникает товар-«сирота» в Bitrix без соответствующей строки в БД.

Альтернатива — добавить компенсацию: при сбое БД откатывать Bitrix (удалять созданный
product row через уже существующий `deleteProductRowVerified`).

## Решение

Откат **не делается**. Порядок — Bitrix-first: сначала Bitrix, затем БД. При сбое БД
товар в Bitrix остаётся как есть.

Обоснование — доменное: **Bitrix является источником правды** для договоров и модулей.
Рассинхрон БД с Bitrix — не аварийное состояние, а отложенная работа, которую устраняет
механизм `sync` (вебхуки/фоновая синхронизация Bitrix → БД). Откат Bitrix означал бы
переопределение источника правды из подчинённой системы (БД), что противоречит самой
модели синхронизации.

## Последствия

**Плюсы:**
- Подчинённая система (БД) никогда не «чинит» источник правды (Bitrix).
- Нет хрупкой компенсирующей логики удаления в Bitrix на горячем пути создания.
- Рассинхрон самовосстанавливается через `sync`.

**Минусы / на что обратить внимание:**
- Возможны товары-сироты в Bitrix без строки в БД до следующего `sync`.
- Сбой сейчас виден только как залогированная ошибка + 500 клиенту; отдельного учёта
  таких рассинхронов нет.

## Отложено (вернёмся позже)

**Логирование/учёт сирот.** Сейчас при сбое БД после успешной записи в Bitrix событие
лишь попадает в `console.error`. Планируется добавить явное логирование таких случаев
(Bitrix-товар создан, строка в БД не записана) для последующей ручной/автоматической
сверки. Это не меняет решение об отсутствии отката — лишь делает рассинхрон наблюдаемым.
Объём и форма (лог / метрика / очередь на сверку) определяются отдельно.

## Почему это записано

Будущий разработчик (или агент), увидев товар-сироту в Bitrix, естественно решит, что
«забыли откат», и добавит компенсацию — тем самым сломав инвариант «Bitrix — источник
правды». ADR существует, чтобы это решение не переоткрывалось по ошибке.
