# 8. «Админ» становится грантом виджета наравне с «менеджером» (уточняет ADR-0007)

Дата: 2026-07-16
Статус: Принято (уточняет решение ADR-0007)

## Контекст

ADR-0007 сознательно сделал «админа» только вычисляемым из Bitrix (`user.admin`),
без хранимого гранта — явно предвидя и отвергая вариант с хранимым админ-грантом
(«вариант C») ради гарантии «портал никогда не остаётся без админа».

На практике всплыло два ограничения:

- REST Bitrix не даёт узнать, является ли **произвольный** пользователь (не тот,
  чей токен сейчас используется) админом портала — методы `user.admin`/
  `BX24.isAdmin` отвечают только про вызывающего. Значит, страница управления
  ролями не может ни отобразить, кто из сотрудников уже Bitrix-админ, ни тем
  более исключить их из списка назначаемых.
- Бизнесу нужен сценарий «дать полный доступ к виджету сотруднику, который не
  является и не должен становиться админом самого Bitrix-портала» (например,
  внешнему подрядчику по биллингу) — а строго вычисляемый админ этого не позволяет.

## Решение

«Админ» — **третье значение гранта** в `user_role`, наравне с «менеджером»
(тот же справочник `role`, та же таблица, тот же API `portal/roles.*`).
Итоговая роль пользователя — максимум из двух независимых источников:

- вычисленный статус Bitrix-портала (`user.admin` при резолве токена);
- явный грант в `user_role` (админ **или** менеджер; наблюдатель — по-прежнему
  отсутствие строки).

Гарантия ADR-0007 «нельзя остаться без админа» не нарушается: она была про
Bitrix-вычисляемый путь и остаётся в силе (тот путь всё так же нельзя понизить
через виджет). Грант — чисто аддитивный второй путь получить админку, не
затрагивающий первый.

Следствие незнания «кто ещё Bitrix-админ»: страница ролей не может показать это
визуально и не блокирует выдачу гранта такому пользователю — грант просто не
добавит и не отнимет у него ничего (он и так админ). Максимум, который берёт
`requirePortal`, делает это безопасным по построению, а не требующим отдельной
проверки.

## Последствия

- Понизить Bitrix-админа через виджет по-прежнему нельзя (не изменилось).
- Дать полный доступ к виджету можно и без админства Bitrix-портала — то, что
  ADR-0007 явно называл ценой простоты, теперь снято отдельным гантом.
- Админ, управляющий ролями, может выдать/снять «админа» самому себе — как и
  «менеджера» раньше, без специальной защиты от «отстрелить себе ногу»
  (согласовано с существующим подходом виджета к другим необратимым действиям).

## Почему это записано

ADR-0007 явно предупреждал будущего разработчика не пытаться сделать админа
хранимым — теперь мы делаем ровно это, поэтому важно зафиксировать: не потому
что прежнее рассуждение было ошибочным, а потому что всплыло реальное
ограничение (Bitrix не даёт узнать чужое админство) и реальная бизнес-потребность
(доступ без Bitrix-админства), которые ADR-0007 не мог предвидеть в момент
написания — но уже называл путь для этого случая («вариант C»).
